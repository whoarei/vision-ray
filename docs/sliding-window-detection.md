# 滑动窗口切片检测原理与实现

## 1. 背景：为什么需要切片检测

VisionRay 的人脸检测模型（ONNX，静态 shape）输入为固定形状 `1×3×320×320`，无法直接接收大图。

朴素做法是**把整张图片缩放到 320×320** 再推理，但对大图存在两个致命问题：

1. **小目标丢失**：一张 4000×3000 的照片压缩到 320×320，缩放比约 12 倍。原图中 60px 的人脸压缩后不足 5px，低于模型 anchor 的可检下限，完全无法检出。
2. **宽高比失真**：直接 resize 不保持宽高比，目标形变进一步降低精度。

模型的可检目标尺寸由 anchor 设计决定：

| 特征层步长 | anchor 尺寸（320 输入下） |
|---|---|
| 8 | 16, 32 |
| 16 | 64, 128 |
| 32 | 256, 512 |

即输入图中约 **16px ~ 320px** 的人脸可检。目标检测的有效"视野"被输入分辨率锁死，这就是大图检测必须切片的根本原因。

## 2. 滑动窗口切片原理

核心思想：**不缩放整图，而是从大图上裁下若干与模型输入量级相当的切片（tile），逐片检测，最后把结果合并回原图坐标系**。

```
原图 W×H
┌─────────────────────────────┐
│ ┌──────┐                    │
│ │tile1 │  步长 stride →     │
│ │  ┌──────┐                 │
│ └──│tile2 │                 │
│    └──────┘                 │
│  ↕ 重叠 overlap             │
└─────────────────────────────┘
```

### 2.1 关键参数

| 参数 | 含义 | VisionRay 默认值 |
|---|---|---|
| `tile_size` | 切片边长（像素） | 640 |
| `tile_overlap` | 相邻切片重叠比例 | 0.2（即步长 512） |
| `input_size` | 模型输入边长 | 320 |

### 2.2 步长的选择

**步长 = tile_size × (1 − overlap)**。三个因素的平衡：

- **tile_size 决定压缩比**：tile 缩放到 320 输入的压缩比 = tile_size / 320。640 的 tile 压缩 2 倍，原图 40px 人脸在输入中约 20px，仍可检出；tile 太大则小目标重新丢失，失去切片意义
- **overlap 防止边界切目标**：人脸若恰好跨在切片边界，会被切成两半导致漏检。20% 重叠（128px）可保证边缘目标至少在一个切片内完整出现，继续增大收益递减、纯增耗时
- **步长决定切片数量即耗时**：切片数 ≈ ⌈(W−tile)/stride⌉ × ⌈(H−tile)/stride⌉

VisionRay 选择 **640 / 步长 512**，实测参考（CPU 单次推理约 0.1s）：

| 原图尺寸 | 切片数 | 耗时约 |
|---|---|---|
| 1920×1080 | 3×2 = 6 | 0.6s |
| 2560×1440 | 5×3 = 15 | 0.6s（实测） |
| 4000×3000 | 8×6 = 48 | ~5s |

### 2.3 切片起点序列

为保证右/下边缘被完整覆盖，起点序列在等间隔基础上补齐最后一个位置：

```python
def _tile_starts(length, tile, stride):
    if length <= tile:
        return [0]
    starts = list(range(0, length - tile + 1, stride))
    if starts[-1] != length - tile:
        starts.append(length - tile)   # 补齐边缘，与前一格重叠更多也无妨
    return starts
```

### 2.4 坐标映射与全局 NMS

每个切片独立推理后，把框和关键点从切片坐标系映射回原图坐标系：

```python
boxes[:, [0, 2]] += x_offset   # x1, x2
boxes[:, [1, 3]] += y_offset   # y1, y2
landmarks[:, 0::2] += x_offset
landmarks[:, 1::2] += y_offset
```

注意：切片内的框已经过切片自身的缩放还原（320 → tile 尺寸），此处只需加偏移量。

重叠区域中同一个人脸会被相邻切片重复检出，因此**所有切片结果合并后做一次全局 NMS**（而非每个切片各自 NMS 后直接拼接），保证重叠区目标只保留置信度最高的一个框。

## 3. VisionRay 中的实现

代码位于 `models/detectors/` 下的人脸检测插件中，结构：

```
detect(image)
├── 长边 ≤ tile_size → _infer(整图) → _to_detections     # 原路径，零开销
└── 大图 → for each tile: _infer(切片) + 坐标映射
        → 合并 → _to_detections（全局 NMS）
```

- `_infer()`：单区域推理（resize → 前处理 → ONNX → anchor 解码 → 置信度过滤），返回该区域像素坐标下的框/分数/关键点
- `_to_detections()`：NMS + 组装 `Detection` 列表
- `detect()`：调度整图/切片两条路径

配置见 `models/detectors.yaml`：

```yaml
- key: face
  detector: face_detector
  params:
    input_size: 320
    tile_size: 640        # 0 = 关闭切片
    tile_overlap: 0.2
```

## 4. 效果与局限

**实测**（合成 2560×1440 大图，6 个不同位置/缩放的人脸）：

| 方式 | 检出数 | 耗时 |
|---|---|---|
| 整图缩放（改进前） | 0~1 个 | 0.04s |
| 切片检测（改进后） | 4 个 | 0.59s |

512×512 小图回归测试无影响（走整图路径）。

**已知局限**：

1. **极小人脸仍无法检出**：tile 压缩比 2 倍，原图 <40px 的人脸在输入中 <20px，低于 anchor 下限。可选改进是加 `upscale` 参数（先放大原图再切片，即多尺度检测），代价是耗时随放大倍数平方增长
2. **耗时与切片数成正比**：超大图（如 8000×6000）需上百次推理，CPU 上需数十秒。可通过增大 tile、减小重叠、或仅对 ROI 区域检测缓解
3. **跨切片大目标**：远大于 tile 的目标在任何切片内都不完整，可能漏检。人脸场景下罕见（tile 640px 已覆盖绝大多数人脸尺寸）

## 5. 其他模型的适用性

车牌检测模型（YOLOv8 ONNX）输入为动态 shape，目前 letterbox 到 640，大图中的小车牌存在同样问题。如需启用，可将切片逻辑（`_tile_starts`、坐标映射、全局 NMS）抽取为公共工具函数复用到 `yolo_onnx.py`——接口已按此目标设计，迁移成本低。
